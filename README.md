# A2MEDIA.SYSTEM


## M2 80-column FAT browser — experimental branch only

**This branch is NOT the tested P0 disk and is NOT compatible with the J2R11
golden FPGA+MCU pair for directory browsing.** Use the matched *M2* a2fpga
FPGA SRAM test image and MCU Stage2, both built from the separate
a2fpga_core branch named petar/media-m2-bidir-fat-picker-20261122.

Experimental ProDOS 2.4.3 bootable disk images (Bitsy Bye launcher unchanged):

- [A2MEDIA-M2-ProDOS243.po](disks/A2MEDIA-M2-ProDOS243.po) — ProDOS order

- [A2MEDIA.SYSTEM](dist/A2MEDIA.SYSTEM) — raw 6502 ProDOS SYS $FF, load $2000

Standard ProDOS, BITSY.BOOT, BASIC.SYSTEM and other files remain in place.
The older, Apple IIe-tested P0 binary and disk images remain unchanged on
the repository's **main** branch.

### M2 keys / behavior

- **Up/Down** (or U/D): choose highlighted file or folder
- **Return:** enter a highlighted folder or play one highlighted .MOD
- **J:** start a whole-folder jukebox at the highlighted .MOD file
- **B** (or Left Arrow): go to parent directory
- **F/G:** previous / next directory page (12 entries per page)
- **S:** stop; **R:** resume stopped jukebox
- **N/P:** next / previous jukebox track
- **I:** refresh MCU playback status and current playlist position (also updates automatically about once per second)
- **L:** reload current FAT folder; **Q/Esc:** ProDOS MLI QUIT

M2 lists FAT directories and case-insensitive .MOD files using a dedicated
MCU directory iterator; source is the **currently mounted SD or USB FAT
backend**, reported at the top. The MCU takes a snapshot of the entire folder,
sorts subfolders first and MOD filenames alphabetically (case-insensitive),
and then sends entries to the Apple II browser in that globally sorted order
across all 12-entry pages. The .MOD portion matches the existing J2R11
jukebox sort, so the next jukebox track is the next listed MOD, even across
pages. The selected starting file still resolves by full relative path.
A directory with more than 512 visible entries fails open rather than
silently truncating the listing. No existing HxCMOD audio sorting changes.
The displayed JUKE position / total fields use five-digit decimal numbers,
not hexadecimal.

**SD vs USB source (one FatFS volume):** The MCU STORAGE menu has AUTO,
USB ONLY and SD ONLY. AUTO chooses USB when a USB storage stick is attached,
even if the ProTracker library is on SD. Both the MCU MOD console picker and
A2MEDIA.SYSTEM browse the **same active mounted medium**, not all connected
media at once. Put the ProDOS .po and your MOD library on the same active
medium, or change STORAGE SOURCE to SD ONLY and RESCAN/REMOUNT ALL after
making sure the bootable ProDOS image is also on SD. Otherwise neither
browser will see the SD-only library. Previous M2 firmware also displayed
an incorrect SOURCE indicator when a USB device was merely connected but
SD had been selected; the MCU now reports the real FatFS backend.

**Empty versus failed directories:** The browser now displays DIRECTORY READ
FAILED with the M2 MCU result code when a directory open/list command
fails, rather than misleadingly showing an empty folder. The MCU console
also displays FatFS error and timeout status, with further diagnostic logs.


The browser shows **NOW PLAYING** with the actual MOD filename reported by the MCU's generation-stable now-playing snapshot. It updates when the player advances tracks, including during jukebox playback without Apple keyboard input; only changed information triggers a screen redraw. M2 now uses a 16-bit software poll counter (~1 second on a stock 1 MHz IIe; quicker at accelerated CPU speeds) instead of relying on $C019 vertical-blank reads, which may not toggle with a2fpga video hardware. An idle player displays `(none)`. The same snapshot is used by the MCU console, so the highlighted file is not misrepresented as the active song.

**Incremental 80-column screen updates:** The application issues Ctrl-L only on first
launch. After that it uses Apple IIe/IIgs 80-column **BASICOUT-safe**
cursor controls (Ctrl-Y home without clearing, Ctrl-J linefeed, Ctrl-\\
forward-space) and Ctrl-] clear-to-EOL, not direct AUX-video-RAM writes.
The previous implementation mistakenly used Ctrl-^ GOTOXY from the
Pascal PWRITE firmware path; normal monitor JSR $FDED/BASICOUT ignores
that sequence, visibly bunching the text together. This is fixed on
the M2 branch. Up/Down changes only the two `>` selection-marker characters. Directory
paging and folder changes replace only the 12 fixed file rows (5–16), and
folder changes also refresh the path line. NOW PLAYING is updated independently
on row 22; MCU state, command/result and jukebox position are fixed fields
on row 23, repainted only when their values change. The title, help text,
separator rules and link label are never redrawn during navigation.

The `tools/test_incremental_screen.py` guard runs in the M2 GitHub Actions
build after ca65/ld65 and prevents accidental reintroduction of a
full-screen redraw into the key or polling paths.

The custom **bidirectional M2 reply FIFO** preserves the existing M1
Apple $C0B0–$C0BF ABI; data is read via $C0B5, opposite to its existing
Apple upload-write direction. New M2 commands are negotiated by the MCU
only after an M2 FPGA SPI7 probe, so the P8 program explicitly displays
an M2-missing warning against old firmware instead of sending FAT requests.

**Status:** cc65/ld65 assembly, ProDOS disk metadata and portable RTL/MCU
protocol tests pass; actual Gowin place/route, BL616 cross compilation,
Apple IIe/IIgs browsing, and real audio coexistence remain unverified.
Retain J2R11 for beta testers. Avoid changing FPGA flash until M2 has
passed physical hardware tests.

## First executable: P0

The initial 6502 application, A2MEDIA.SYSTEM, is a raw ProDOS 8 **SYS ($FF)** binary with load/entry address **$2000**. It activates internal 80-column firmware, detects the existing ROMless M1 physical-slot-3 mailbox ($C0B0–$C0BF), and operates the commands already present in J2R11.

| Key | M1 operation | Command |
|---|---|---|
| I | Ping / probe | $01 |
| S | Stop | $03 |
| N / P | Next / Previous | $06 / $07 |
| L | Replay last MCU-selected MOD | $02 |
| F | Jukebox from last folder | $04 |
| T | Jukebox from last folder plus subfolders | $05 |
| O / R | Single MOD play once / repeat | $08 / $09 |
| Q / ESC | Return through ProDOS MLI QUIT | $65 |

The program shows MCU mailbox readiness, FPGA-reported PLAYING state and last command/result bytes. It does **not** fabricate filenames or directories: M1 has an Apple-to-MCU FIFO, not a reply channel.

**Important:** M1 RTL hard-codes physical Apple slot 3 ($C0B0), although earlier audio development often used slot 4. Neither IIe nor IIgs physical mailbox access has been proven by the audio tests. From BASIC, the non-destructive signature check is:

    PRINT PEEK(49328),PEEK(49329),PEEK(49330)

Expected: **77 66 1** only when the installed FPGA and physical bus respond. Without M1, the app displays NOT DETECTED, sends no commands and supports Q/ESC exit. **P0 has not yet been tested on physical Apple hardware.**

## Build / distribution

Install cc65 (ca65, ld65), Python 3 and Make:

    make
    make check

Generated raw binary: **dist/A2MEDIA.SYSTEM**, with no load header. When copying to a ProDOS disk, explicitly set **SYS filetype $FF**; the filename extension alone does not set ProDOS metadata. For booting, pair the SYS program with ProDOS 8 and configure it as the startup application.

GitHub Actions compiles and validates the binary, uploads a workflow artifact, and attempts to commit it to dist/A2MEDIA.SYSTEM on main. Check the workflow log and SHA-256 for the exact build.

## Bootable ProDOS 2.4.3 floppy disk images

Two **140 KB (143,360-byte)** images are committed under `disks/`:

- **[A2MEDIA-ProDOS243.po](disks/A2MEDIA-ProDOS243.po)** — ProDOS block/sector order; recommended for ProDOS-aware tools, Cadius, and most modern emulators
- **[A2MEDIA-ProDOS243.dsk](disks/A2MEDIA-ProDOS243.dsk)** — genuine DOS 3.3 sector ordering, converted from the same `.po`, suitable for software expecting DOS-order `.dsk`

Disk volume is **/PRODOS.2.4.3**. The file `A2MEDIA.SYSTEM` is installed in its root directory with ProDOS file type **SYS ($FF)**, auxiliary type **$2000**, **1,572 bytes**, and **five storage blocks** (sapling index plus four data blocks).

The original `PRODOS`, `BITSY.BOOT`, `QUIT.SYSTEM`, `BASIC.SYSTEM` and all other official distribution files remain in place, in their original catalog order. **Bitsy Bye remains the boot launcher**, and you can choose A2MEDIA.SYSTEM there; the disk does not automatically replace the launcher. No SenseiPlay8 files appear in the catalog.

**Source provenance:** This disk was generated from the official [ProDOS 2.4.3 release image](https://github.com/ProDOS-8/ProDOS8-Releases/blob/master/ProDOS_2_4_3.po), Git blob `d464c92578d4ed15dc4acd49eee43e51256808fd`. The specific earlier SenseiPlay8-modified conversation image was no longer available to edit byte-for-byte; the *official* release was used as the clean source instead. Only root directory metadata, allocation bitmap, and five newly allocated blocks changed. Boot sectors and existing file content are unchanged.

Validate the included images locally:

~~~powershell
py -3 tools/prodos_disk.py check
~~~

To regenerate both images from the original ProDOS 2.4.3 ProDOS-order `.po` file and the current A2MEDIA executable:

~~~powershell
py -3 tools/prodos_disk.py build --base ProDOS_2_4_3.po
~~~

The builder also removes any root-level files whose names start with `SENSEI` if you later supply a prior SenseiPlay-modified ProDOS-order image. Both images are **disk-structure verified**, not yet hardware-booted on Apple IIe/IIgs.

## Roadmap

1. P0: 80-column ProDOS 8 M1 controls; physical IIe/IIgs tests.
2. M2: a separate a2fpga development branch adds MCU-to-Apple reply FIFO and safe disk-thread FAT directory enumeration. Then A2MEDIA gets an 80x24 SD/USB file browser, selected MOD playback, and start-at-file.
3. Internet radio streams, presets, audio sources other than MOD, and other a2fpga media services.

Original J2R11 beta FPGA/MCU binaries remain untouched.

**Large-folder M2 timing fix:** The BL616 now ACKs directory OPEN immediately
and builds its alphabetically sorted FAT catalog using a nonblocking FatFS
broker. The MCU's slot-3 service task no longer waits for slow SD reads.
On a directory NEXT request it returns MCU result `$EA` while the scan
is in progress. The application retries `$EA` with a finite bound;
`$E1` now denotes only a *single command ACK timeout*, and `$EB` means
the entire folder scan stayed pending beyond the retry bound. Actual
FatFS errors return `$E7`. This fixes
the Apple-side `DIRECTORY READ FAILED - MCU RC: $E1` that occurred when
`ProTracker/1` contained ~506 MOD files, even though the MCU console could
browse it. Previous-page navigation now sends `M2_SEEK ($2B)` with a 16-bit
little-endian catalog entry index, instead of reopening and rescanning the
entire SD directory. The **matching M2 BL616 Stage 2 firmware is required**
for both features; the FPGA bitstream and Floppy Emu slot-6 ProDOS boot
device are unchanged. Hardware verification is still required.
